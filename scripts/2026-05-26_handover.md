## Gotchas captured the hard way

1. **`Data/` is NOT under `$HOME/atlas/hazards_prototype/`.** On CGlabs with `climdat_source = "nexgddp"`, Data lives under `/home/jovyan/common_data/nex-gddp-cimp6_hazards/`. Any Rscript that reads pipeline outputs must `source(R/0_server_setup.R)` first (it `setwd()`s to the right working_dir). Skipping this is what caused the first three post-rebake-followups log iterations to fail.
2. **`s3fs::s3_file_copy` strips ACL.** The new object inherits the bucket's default (private), so anonymous DuckDB-httpfs reads get HTTP 500. Use download + `s3_file_upload(..., ACL="public-read")` for any copy that needs to stay notebook-readable, including rollback paths.
3. **`Rscript -e '...'` doesn't survive embedded single quotes** in SQL. Use `Rscript - <<'EOF'` heredoc with `'EOF'` quoted so the shell does no expansion inside.
4. **SQL operator precedence**: `AND` binds tighter than `OR`. The validator's `[c]` had `WHERE (iso3='NGA' AND crop=...) OR (iso3='CIV' AND crop=...) AND <common filters>` which parsed as "NGA gets EVERYTHING, CIV gets filters" — wrap the OR'd selectors in parens.
